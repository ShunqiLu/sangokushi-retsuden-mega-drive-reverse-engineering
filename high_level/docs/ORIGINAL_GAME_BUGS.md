# 原版兼容行为

下表记录卡带游戏中可区分的行为与边界。复原逻辑沿用这些行为，包括计数回绕、表项残值、指针覆盖和部分写入。编号用于定位同一现象。

| 编号 | 原版行为 |
| --- | --- |
| BUG-001 | 粮食运输累加溢出后降为 99,999。 |
| BUG-002 | 到达城市的一条邻接匹配分支受恒假条件限制。 |
| BUG-003 | 邻接候选删除使用较短的压缩复制范围。 |
| BUG-004 | AI 寻路调用覆盖了后续选择仍使用的城市表指针。 |
| BUG-005 | 邻接费用的两次读取均使用网格索引。 |
| BUG-006 | 到达队伍的首领搜索止于倒数第二槽；移除时跳过首项搬移。 |
| BUG-007 | 清理势力名单时使用已自增的源指针，可能擦掉未读终止符。 |
| BUG-008 | AI 购武器只读 BYTE 却比较 WORD，残留高字节使购买被跳过。 |
| BUG-009 | AI 武器购买以首个武将槽作为写入目标。 |
| BUG-010 | AI 开发预算丢弃随机比例，实际使用四倍城市编号。 |
| BUG-011 | 训练触顶修正使进度增量反而超过原始增量。 |
| BUG-012 | AI 招兵容量门比较名单游标相对内存，而非兵力表。 |
| BUG-013 | AI 第三个玩家归属检查比较先前选中城市而非当前归属方。 |
| BUG-014 | 寻路前沿耗尽后仍沿用搜索分支。 |
| BUG-015 | AI 城市邻接候选表包含两条单向关系。 |
| BUG-016 | 军队资源决策的最终动作是 13；其中一路在同一调用中也写入 12。 |
| BUG-017 | 两处随机分支测试恒为零，随机种子副作用仍执行。 |
| BUG-018 | 最大敌军候选以无符号最大值作为比较基准。 |
| BUG-019 | 名单强度累计量的低 WORD 被每个成员号和终止符覆盖。 |
| BUG-020 | 城市强度扫描读取目标城市后，又将它覆盖为武将计数器。 |
| BUG-021 | 军队购装备准备了装备表指针，却写入属性表。 |
| BUG-022 | 城市关联武将缺失时，分支循环停在原地址。 |
| BUG-023 | 经济支援城市扫描的子函数改变了后续“已处理”检查基址。 |
| BUG-024 | 支援名单的追加写在旧终止符之后。 |
| BUG-025 | 军队名单排序沿用已经减到 FFFF 的计数作 WORD 地址。 |
| BUG-026 | 补粮价格的非零 LONG 在 WORD 除数口变成零。 |
| BUG-027 | 双武将行军费用直接以平均速度作除数，零值到达除法。 |
| BUG-028 | 特殊战场尾组选值前，八次循环始终清同一个槽位。 |
| BUG-029 | 战场候选去重扫描可越过候选区进入相邻输出。 |
| BUG-030 | 战场预算计算完商之后，重新读回旧预算。 |
| BUG-031 | 地形筛选准备坐标表指针，却从地图基址读坐标。 |
| BUG-032 | 一种战场预算公式混入完整更新后的随机状态。 |
| BUG-033 | 武将编号乘四用于坐标后，缩放值被写回名单。 |
| BUG-034 | 两条名单重排路径向前复制到相邻重叠区。 |
| BUG-035 | 名单训练直接以选中人数作除数，零值到达除法。 |
| BUG-036 | 精灵水平翻转读取尺寸后，坐标修正恒为 8。 |
| BUG-037 | 战场强度比的第二侧分母重复乘 B400 属性因子。 |
| BUG-038 | 固定字段存档编码器将非零残余字节写回输入游标。 |
| BUG-039 | 第一类月度事件重复执行六月分支。 |
| BUG-040 | 战后第二项城市资源的合计写回战场暂存表。 |
| BUG-041 | 空军队包的平均速度计算耗尽 WORD 计数，零值到达除法。 |
| BUG-042 | 场景人数调整在特定总量下于 15 和 16 间往复。 |
| BUG-043 | 对象行动扩展纵向探测的第三个偏移为 3。 |
| BUG-044 | 调色变换入口收到大于 15 的低 WORD 时自锁。 |
| BUG-045 | 第二侧人数调整同样可能于 15 和 16 间往复。 |
| BUG-046 | 对象追逐分支的比较标志被中间 MOVE 覆盖。 |
| BUG-047 | 高位忠诚度汇总从忠诚表取 BYTE，再将其用作当前包偏移。 |
| BUG-048 | 高位忠诚度汇总直接以计数作除数，零值到达除法。 |
| BUG-049 | 行动预算直接以武将 C400 属性 BYTE 作除数，零值到达除法。 |
